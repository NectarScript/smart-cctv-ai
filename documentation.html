Introduction

01

Project Background

Smart CCTV AI is an intelligent surveillance platform designed to detect people, analyse behaviour and generate alerts in real time. The mini project used YOLOv8 for person detection, MediaPipe pose estimation, a PyTorch classifier and a FastAPI + WebSocket backend.

Need for the Mega Project

  • Single-camera processing is limited in practical deployments.
  • The system needs multi-camera ingestion, identity awareness and cloud accessibility.
  • Secure role-based access and richer alerting are required.
  • Goal: move from reactive monitoring to proactive protection.

Mini Project Validation

  • Demonstrated real-time detection on a single video stream.
  • Detected fighting, loitering, sudden running, crowd surges and unattended objects.
  • Achieved 20+ FPS on commodity hardware.
  • Validated the core computer-vision pipeline.

Literature Survey

02

Existing / Mini-Project Approach

  • Single stream from webcam, file or RTSP source.
  • YOLOv8-based person detection with a single behaviour classifier.
  • Local-machine deployment with a live dashboard.
  • Email-based alerting.

Proposed Direction from the Survey

  • Extend to concurrent multi-camera processing.
  • Add face recognition against a registered database.
  • Introduce secure cloud deployment.
  • Add mobile push notifications and analytics.
  • Benchmark alternative behaviour-classification models.

Identified Limitations

  • No persistent identity recognition.
  • No concurrent multi-camera ingestion.
  • No cloud deployment or remote accessibility.
  • No role-based access control or audit logging.
  • Limited analytics and reporting.

Aim and Objective

03

Aim

To build an intelligent, scalable and secure multi-camera surveillance platform that provides real-time detection, behaviour analysis, identity-aware alerts and actionable security insights.

Objectives

  • Extend the existing pipeline to support concurrent multi-camera ingestion.
  • Integrate face recognition for registered/known individuals.
  • Deploy the backend as containerized services on a cloud platform.
  • Build a mobile alert application using Firebase Cloud Messaging.
  • Introduce RBAC with audit logging of user and alert actions.
  • Generate incident heatmaps, trends and periodic PDF reports.
  • Benchmark and improve behaviour-classification models.

Proposed Methodology

04

Real-Time AI Pipeline

Video Input → Frame Extraction → Person Detection → Object Tracking
Pose Estimation → Behaviour Analysis → Face Recognition
Event Processing → Alerts → Dashboard & Reports

Processing and Alert Flow

  • Capture video from cameras, RTSP/ONVIF streams or files.
  • Extract and preprocess frames for low-latency processing.
  • Use YOLOv8 and ByteTrack for detection and persistent tracking.
  • Use MediaPipe pose landmarks and a PyTorch model for behaviour classification.
  • Match identities using FaceNet/DeepFace against the registered database.
  • Log events in PostgreSQL and deliver email/mobile alerts.

Module 2 — Detection & Tracking

07

Person Detection

  • YOLOv8n/s model optimized for real-time inference.
  • Confidence-score filtering to reduce false positives.
  • GPU-accelerated inference via CUDA when available.
  • Batch processing for multi-camera frame queues.

Persistent Tracking (ByteTrack)

  • Assign consistent track IDs across consecutive frames.
  • Handle occlusions, re-entries and overlapping bounding boxes.
  • Maintain per-track history for behaviour temporal analysis.
  • Deduplication across camera overlaps (future).

Detection → Tracking Flow

Frame Queue → YOLOv8 Inference → NMS Filter → ByteTrack Association → Track Store

Module 3 — Behaviour Classification

08

Pose-Based Classification

  • MediaPipe extracts 33 body keypoints per person per frame.
  • Keypoint sequences fed into a PyTorch temporal classifier.
  • Outputs: Normal, Suspicious, Critical with confidence scores.
  • Sliding-window approach for temporal context (N-frame sequences).

Model Benchmarking

  • Compare LSTM vs GRU vs Transformer-based classifiers.
  • Evaluate accuracy, latency and memory footprint.
  • Use labeled dataset with annotated suspicious events.
  • Select best model for deployment via F1-score and FPS trade-off.

Classification Pipeline

Track Crop → MediaPipe Pose → Keypoint Buffer → PyTorch Model → Label + Score

Module 4 — Face Recognition

09

Identity Matching

  • Detect faces within tracked person bounding boxes.
  • Generate 128/512-d embeddings via FaceNet or DeepFace.
  • Compare against a pre-registered database of known individuals.
  • Cosine-similarity threshold for match/no-match decisions.

Registration Flow

  • Admin uploads reference images via dashboard.
  • System generates and stores embeddings in PostgreSQL.
  • Supports multiple images per identity for robustness.
  • Re-enrollment and deletion through RBAC-protected API.

Recognition Pipeline

Person Crop → Face Detect → Align & Embed → DB Lookup → Identity Tag
